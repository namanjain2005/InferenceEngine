Text generation and attention-kernel comparison prompts

The contexts increase in length, and each prompt asks for a concise, meaningful
answer. These are useful for checking readable generation as well as comparing
how prompt length affects prefill time. Answers can vary in length, so compare
prefill and decode timings separately.

[1 - Tiny context]
What is 7 + 5? Answer in one complete sentence.

[2 - Short context]
Changing one kernel detail at a time can make a performance experiment easier to
understand. Why? Answer in one complete sentence.

[3 - Medium context]

Reliable software is built by checking each layer of a system independently.
Input data is validated before it reaches a computation. The computation should
preserve its mathematical meaning while making good use of the hardware. Results
are then checked against a simple reference. Performance measurements should
record the input size, output size, device, and settings so that later runs can
be compared fairly. A useful experiment changes one implementation detail at a
time and keeps the workload fixed. This makes it easier to identify which change
caused an improvement or regression.

[4 - Long context]
Read the passage, then follow the instruction at the end.

A small inference engine moves data through several stages. It begins by
converting text into token identifiers. The model maps those identifiers into
vectors, applies normalization, and computes query, key, and value projections.
Rotary position information is added to the query and key vectors. Keys and
values from earlier positions are kept in a cache so that each generated token
can attend to the existing context without recomputing every projection.

For one query head, attention compares the query with the keys at every cached
position. Each score is scaled, normalized with softmax, and used to form a
weighted sum of the values. In multi-head attention, each query head has its own
key and value head. In grouped-query attention, several query heads share a key
and value head. The same computation can handle either arrangement when the
query-head and KV-head counts are provided correctly.

GPU performance depends on how threads access memory as well as how many
operations they perform. Neighboring lanes are most effective when they read
neighboring values. A warp can cooperate on a dot product by loading adjacent
head dimensions and reducing the partial sums. Softmax also needs reductions to
find the maximum score and the sum of exponentials. Measuring one optimization
at a time helps show whether coalesced reads or parallel reductions improve the
actual workload.

Based on the passage, explain grouped-query attention in two short sentences.
